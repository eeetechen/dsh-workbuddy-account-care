## 介绍
他是一个保护workbuddy账号的插件。
在workbuddy更新的时候，可能会更新请求的方式，参数。如果插件dsh-workbuddy-connect没有同步更新可能会导致workbuddy账号被封号。
这里的插件dsh-workbuddy-account-care 就是为了解决这个问题，而设计出来的。
## 流程
1. 在后台定时检查wb更新接口（多平台取最高）下发的版本号（当前是3分钟）补充：“可以串行请求，用户无感，实时性没有很高”。和本地的dsh-workbuddy-connect版本号做一个匹配。
2. 如果dsh-workbuddy-connect更新，那就更新这个插件到最新版。适配多端，Linux，mac, windows 。包括npx @deepseek-ai/dsh web启动的（无dsh命令）全局安装dsh(有dsh命令)，deepseek-harness desktop 打包版（无dsh命令）
    如果需要重启就弹出水印提醒重启。
    如果不需要重启就弹出水印提醒插件已更新，无需重启，有一个按钮，
    - 知道了：点击之后直接消失。
3. 如果检测到workbuddy客户端版本更新，但是插件没更新时。
    - 如果有后台会话运行着，且是wb provider的话，那就弹出水印“还用，你的账号是批发的吗？”且有三个按钮
        - 软结束：在未结束的会话中插队发送文案“本机 provider 已更新，本条消息由监控插件自动发送，收到后暂停你的所有任务, 等待重启 agent 工具”然后等待会话结束后，关闭dsh-workbuddy-connect插件，水印消失
        - 硬结束：直接关闭dsh-workbuddy-connect插件，水印消失。
        - 知道了：点了之后消失又浮现，强行提醒。

    - 没后台任务时，弹出水印，两个按钮
        - 关闭插件：字面意思，关闭dsh-workbuddy-connect插件，水印消失。
        - 知道了：点了之后消失。  

    - 然后是关闭插件dsh-workbuddy-connect后，可以强行打开

    - 如果是打开插件dsh-workbuddy-connect后，使用了wb provider，并且后台没有结束，哪怕切换了界面，也显示水印。
        - 知道了：点了之后消失，再重现。（强提醒，不给他消失，只是有个消失再出现的动画）
    - 如果是打开插件dsh-workbuddy-connect后，使用了wb provider，但是当所有使用wb provider的后台结束了，且当前展示的会话用的不是wb provider时水印自然消失。
    - ，表现和不关闭插件的表现一致。在当前展示的会话中检查provider是不是wb provider 如果是，就弹出水印，两个按钮
        - 关闭插件：字面意思，关闭dsh-workbuddy-connect插件，水印消失。
        - 知道了：点了之后消失，再重现。切换到非wb provider后水印消失。

4. 如果先检测到workbuddy客户端版本更新，水印还在，没有点掉。然后插件也更新了，水印消失，提示插件更新水印。同样是点击知道了消失。

## feature 
现在的dsh-workbuddy-connect插件有调用本机workbuddy cli干活的能力，可以通过dsh-workbuddy-connect 的插件配置改变。后续可以弹窗中添加软启用，然后不关闭dsh-workbuddy-connect而是发送插队文案引导会话使用workbuddy cli继续任务。
